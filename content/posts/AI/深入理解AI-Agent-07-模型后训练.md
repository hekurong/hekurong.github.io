## 0. 章首核心观点



- 现代模型能力开发三阶段地图：**预训练打地基，SFT 与 RL 是根据目标、基础模型和输出要求选择或组合的后训练阶段**。

  - **预训练（Pre-training）**：海量互联网文本上"预测下一个词"。让模型学会语言规律、世界知识和基本推理——像一个人读完了图书馆里所有的书：博学，但还不会好好回答问题。最贵的一步（动辄数千万美元），能力的地基；

  - **监督微调（SFT）**：几千到几万条"问题—标准回答"示范数据，教会模型"该用什么格式、什么风格、什么流程回答"。把博学的模型变成听得懂指令、输出规整的助手。便宜、快、稳，几乎所有部署模型都会经过；

  - **强化学习（RL）**：让模型自己去试，做得好的行为概率调高、差的调低。当奖励、数据、环境设计得当时，可以让模型在没见过的情况下做出更好的决策——本章篇幅最大、最需要工程功力的一步。

- 直觉类比：预训练是"读万卷书"，SFT 是"老师手把手教标准解法"，RL 是"自己下场做题、根据对错反复打磨"。预训练→SFT→RL 是常见配方但不是唯一顺序：强基础模型可直接做 RL，只需稳定格式和风格的任务可能只做 SFT。

- **两条贯穿主线**：

  - **主线一：本章对照实验中，SFT 更容易记住示范，而 RL 表现出更好的泛化**（GeneralPoints 和 V-IRL 相同任务/模型/预算下：SFT 对训练答案过拟合，RL 在分布变化测试中更容易学到可迁移策略）。这是实验条件下测得的结果，不是 SFT 与 RL 的普遍属性——数据足够多样、正则化得当时 SFT 也能泛化，奖励或环境有偏时 RL 也会过拟合；

  - **主线二：数据和环境，比算法更重要**。工业界最反直觉也最值钱的经验——现成 RL 算法（PPO、GRPO）你知道怎么用就够了，真正决定成败的是仿真环境（练习场够不够真实）和训练数据（示范和奖励信号质量够不够高）。**很多场景下，只要 SFT 数据质量到位，你甚至根本不需要做 RL**。

- 阅读指引：Agent 应用开发者（不需自己训练模型）——先读三阶段全景，跳过两节可选阅读，从 SFT 一节继续，重点在"何时选 SFT、何时选 RL"的决策框架和"数据与环境比算法更重要"的判断；模型训练工程师——从头顺序阅读。

## 1. 预训练、SFT、RL：三阶段全景



### 1.1 三阶段总览（表 7-1）



| 阶段 | 用什么数据 | 优化目标 | 学到什么 | 典型代价 |

|---|---|---|---|---|

| 预训练 | 海量原始互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高（数百万～数千万美元） |

| SFT | 几千～几万条"输入—输出"示范对 | 预测下一个词（只在回答上算损失） | 指令遵循、输出格式、风格、流程协议 | 低（几小时～几天） |

| RL | 任务、环境 + 奖励信号（参考答案可选） | 最大化期望奖励 | 可迁移的决策策略、探索出的新解法 | 高（常是 SFT 的几十～上百倍） |



### 1.2 预训练在做什么：预测下一个词



- 现代大模型的全部"智能"建立在一个简单任务上：**预测下一个词（Next Token Prediction, NTP）**。模型每猜一次，把预测与真实下一个 token 比较，差距（损失 Loss）越大越用力调整参数。在几万亿 token 上反复做，模型被迫学会语法、事实、逻辑乃至基本推理。

- **关键点**：模型的输出本质是一个概率分布——给定前文，对词表里每个 token 都给出概率。"训练"归根结底是调整这个概率分布（想要的 token 概率更高、不想要的更低）。三阶段区别只在于"想要什么"和"用什么信号定义想要"。

- 预训练之后模型博学却不好用：问它问题它可能续写出更多问题（互联网文本里一个问题后面常跟另一个问题）——它还没学会"被提问时应该回答"这个协议。



### 1.3 SFT 的本质：换了数据的"预测下一个词"



- **关键认知：SFT 在数学上和预训练是同一个任务——都是预测下一个词、最小化同一个损失函数**。差别只有两点：

  1. **数据不同**：预训练用原始互联网文本；SFT 用人工准备的"输入—输出"对（用户提问 → 理想回答）；

  2. **损失只算在"回答"上（loss masking，损失屏蔽）**：把问题部分 token 屏蔽、只对回答部分回传梯度——这是 SFT 与预训练唯一实质性的工程区别。

- 一句话概括 SFT 本质：**用极高的样本效率，把一套稳定的"输入→输出"映射与协议固化进参数**。它固化的是"格式、风格、流程"这类协议性知识（该怎么说、怎么做），而非大量事实性知识（知道什么）——后者要靠预训练或 RAG。

- **LoRA（Low-Rank Adaptation，低秩适配）**：最常用的省钱办法——不动原始大权重矩阵，只在旁边挂一个很小的"补丁"（低秩矩阵），参数量仅占原始 1%-5% 却能接近全参微调效果。原权重被冻结，对基座已有能力扰动更小、灾难性遗忘风险更低。实践经验：①必须应用到所有主要权重矩阵（尤其参数占比最大的 MLP 层），只加注意力层会掉点；②最优学习率约是全参微调的 10 倍（SFT、RL 都成立，实用迁移规则）；③SFT 用中高 rank（64-256），RL 因每轮信息量小用低 rank（8-32）甚至 rank=1 就够。部署时一台推理服务器可同时加载多个 LoRA adapter 做多租户服务。本书把 LoRA 当作贯穿所有后训练方法的工程默认项。



### 1.4 什么时候需要先 SFT 后 RL



- 答案藏在 RL 的工作方式里：RL 用奖励信号评估模型自己生成的回答，但**要判断好坏首先得能把模型的输出解析出来**——如果任务要求输出 JSON 或工具调用而模型吐出格式混乱的文本，奖励函数根本无从算起，RL 也就无从学起。

- 所以在结构化输出不稳定的设置中，SFT 先扮演"把话说利索"的角色：少量示范让输出格式稳定、可被可靠解析，RL 才有能打分的起点——**业界稳健的"先 SFT 后 RL"两阶段范式**。借用中国画说法：**SFT 先把"形"（格式、结构）立起来，RL 再追求"神"（策略、泛化），即先形后神**。

- 重要边界："必须先 SFT"是在"较小基础模型 + 严格结构化输出"设定下成立的（实验 7-11：Llama-3.2-Vision-11B 量级不经 SFT 直接 RL 会完全失败）。但基础模型足够强时可跳过 SFT——**DeepSeek-R1-Zero 证明强基模可以直接 RL 成功**，自行涌现反思与长链思考；代价是输出可读性差、中英文混杂，所以 DeepSeek 最终在 R1 里加回"冷启动 SFT"把"形"重新立稳。R1 从 Zero 到冷启动的往返，正是"先形后神"的最好注脚。



### 1.5 SFT 与 RL 的本质区别（本章最重要的一张表，表 7-2）



| 维度 | SFT（监督微调） | RL（强化学习） |

|---|---|---|

| 优化目标 | 最大化标注答案的概率（极大似然） | 最大化期望奖励 |

| 训练信号 | 标注回答的逐 token 监督 | 策略生成的回答或轨迹 + 结果级或步骤级标量奖励 |

| 数据形态 | "输入—输出"示范对 | 任务、环境 + 奖励信号（参考答案可选） |

| 直接优化压力 | 模仿示范中的映射与协议 | 强化能够获得奖励的行为与策略 |

| 分布漂移下 | 取决于示范覆盖和正则化；本章有限示范实验出现过拟合 | 取决于奖励、环境和探索；本章实验中迁移更好 |

| 样本效率 | 高（几千条见效） | 低（常是 SFT 的几十～上百倍） |

| 训练稳定性 | 高、收敛快 | 低、易震荡，需要小心调 |

| 最适合 | 固化格式/风格/流程、有高质量示范、环境稳定 | 需泛化到新场景、探索最优策略、标注成本过高 |



- 更深的机制：**mode-seeking（寻峰）**。模型对一个问题的所有可能回答构成概率分布，可能有多个"峰"（每峰代表一类合理回答方式）。极大似然 SFT 可能表现出 mass-covering（覆盖式）倾向（把概率分配给示范中的多个模式）；用反向 KL 约束的策略优化可能表现出 mode-seeking 倾向（把概率集中到少数高奖励模式）。具体行为取决于数据、奖励、KL 的方向与系数——**不能视为 SFT 和 RL 不变的固有属性**。

- **后训练塑造模型何时行动**：GPT 与 Claude 系列常表现出不同默认行动阈值（GPT 先读更多仓库再修改、Claude 用较少文件定位先实现再借测试修正）——不是拟人化"谨慎/直觉"，而是参数中的策略在估计"多读一个文件的预期价值是否还高于提交当前补丁并验证的预期价值"。SFT 示范反复含广泛调查后编辑的轨迹 → 模型模仿较高行动阈值；RL 过程/结果奖励持续认可快速定位 → 概率质量向较早行动轨迹集中。第六章实验 6-7 在相同中性 Harness 中换模测到差异随模型变化——**Harness 可以调节它，但行为主要来源可以位于后训练后的模型参数中**。

- **在线反馈的三个机会**（"在线/离线"与更严格"在轨/离轨 on-policy/off-policy"的区分在 7.8 节）：①可以评估固定示范之外的候选（实验 7-13 的"推切"动作从未出现在人类示范里）；②可以利用"验证比生成容易"的任务（数学答案可对照、代码可测试、定理证明可由验证器检查——RLVR 的优势，但验证器不完整时会导致奖励黑客）；③可以在当前策略实际访问的状态上训练（离线模仿存在经典协变量漂移 covariate shift：策略偏离示范、进入数据中没有的状态后缺少恢复信号；特定序列模仿学习设置中误差最坏可随轨迹长度 T 按 T² 累积，在线数据聚合可降到约 T）。

- 比方：**SFT 细致学习已有地图，RL 拿着奖励这枚指南针探索地图外的候选路线**。地图或指南针不准都会迷路——许多系统先用 SFT 建立稳定起点，再在奖励与环境足够可信时加入 RL。

## 2. 从经典 RL Agent 到现代 Agent（可选阅读）



### 2.1 Agent 与环境的交互



- RL 核心：学习根据当前情境选择动作，获得最大累积奖励（Cumulative Reward）。Agent 与环境持续交互：观察状态→选择动作→环境产生新状态并给奖励。

- 交互产生轨迹（状态→动作→奖励→…完整记录）；**价值函数（Value Function）**回答"如果现在处于这个状态，按当前策略一直行动下去，最终总共能获得多少奖励"。（换成最优策略时得到最优价值函数。）

- RL 区别于监督/无监督学习的两特征：**试错搜索**（没有老师直接告诉正确答案）和**延迟奖励**（动作影响可能多步后才显现）。由此带来**探索与利用权衡（Exploration-Exploitation Tradeoff）**。

- 五个核心要素：动作空间（离散/连续）、策略（行为准则）、奖励信号（即时反馈，但目标是最大化长期而非即时奖励）、价值函数（估计未来累积奖励——**过去六十年 RL 研究最重要的认识之一是价值估计的核心地位**）、环境模型（可选；有=基于模型方法，无=无模型方法）。

- 表 7-3 各类 Agent 系统关键要素对比：新生小羚羊（连续高维肌肉群收缩；平衡+/跌倒-）、扫地机器人（离散方向；清洁面积+/电量耗尽-）、国际象棋大师（离散有限合法走法；赢棋+1/输棋-1）、客户服务 Agent（变长组合式思考/说话/API 调用；问题解决+/处理时间-）、代码助手 Agent（变长组合式思考/搜索/编辑/执行；测试通过+/引入 bug-）。**洞察：LLM Agent 用有限 token 和工具调用组合出变长动作序列，很难一次性枚举所有可能序列，并且可以利用"内部思考"提升能力**。



### 2.2 两种动作表示：经典 RL 与 LLM 的变长策略



- MDP（马尔可夫决策过程）：核心假设是马尔可夫性质——未来只取决于当前状态，当前状态必须包含决策所需的全部历史信息（国际象棋状态需含轮到哪方、王车易位权、吃过路兵权、五十步规则等）。

- 经典 RL 环境用预先定义的动作空间（围棋 361 落子位置有限、Atari 几个到十几个离散原始动作、机器人连续但有界）；**LLM Agent 的变长组合式动作比原始动作拥有大得多的搜索空间，很难没有先验知识从零学习**——LLM 从海量文本预训练学到人类留下的问题解决模式（数学按"识别条件→回忆公式→逐步计算"），预训练策略给结构化路径更高先验概率，显著压缩搜索空间。即使没有额外 RL，预训练 LLM 也能生成基本思维链。

- **最关键的实用创新：把思考 token 作为特殊动作纳入策略输出空间**——思考 token 不直接改变外部世界却可提高最终行动质量；Agent 的动作表示不仅包括"做什么"，还包括"想多久、想什么"。

- 无先验知识 Q-learning 与预训练 LLM 对比（实验 7-1 寻宝游戏）：Q-learning 需近 10000 episodes（前 1000 episodes 胜率 0%、7000-8000 从 34% 升 96%、10000 达 100%，找到 11 步最优解，整个训练不到 10 秒）；LLM Agent（Kimi K3）**第一局 18 步通关**——理解概念结构（"武器总比空手好"、"需要找钥匙"、"主动合成银剑"），每一步都有目的和逻辑。**计算成本悖论**：Q-learning 跑 10000 局 10 秒，LLM 一局 1-2 分钟——但现实任务每次交互的时间/金钱/风险成本远超纯计算成本。**LLM Agent 的成功不是因为更好的"学习算法"，而是因为携带海量先验知识**。设计原则：仿真成本低可大量重复的场景传统 RL 仍有价值；交互成本高需快速适应的现实场景 LLM Agent 样本效率更实际。

- **OpenAI 探索之路（姚顺雨《The Second Half》）三阶段认知演变**：第一阶段（2015-2016）算法中心主义（相信更好算法才是关键，换新环境就得从头训练）；第二阶段（2016-2018）环境的重要性（Gym 标准化任务、Universe 和 World of Bits 试图把互联网变成 RL 训练环境，但通用计算机使用和网页导航始终无法突破）；第三阶段（2018 至今）**先验的觉醒**（GPT-2/GPT-3 展示语言预训练力量，WebGPT、ChatGPT 证明先验可转化为实用 Agent）。最重要的发现：**先验知识可以通过与 RL 完全无关的方式获得——几十年 RL 研究者的优先级可能完全颠倒了：不是算法 > 环境 > 先验，而是先验 > 环境 > 算法**。

## 3. 模型预训练基础（可选阅读）



- 语言模型训练遵循"tokenization — 预训练 — 后训练"三阶段。Tokenization 将文本切分为离散单元（token）——模型处理文本的最小单位。

- 实验 7-3 ★★（从头训练 LLM）：MiniMind 2（一亿参数）消费级 GPU 完整训练流程。两项算法优化（**QK Norm 和 Muon 优化器**）使收敛速度提升 3 倍、生成质量显著改善——总训练约 14 小时、成本约 34 美元。各阶段效果：预训练后可答事实性问题但格式不规范；SFT 后指令遵循与输出格式显著改善；偏好优化进一步减少事实错误与不自然表达。启示：**在固定小规模预算下，算法改进比单纯堆规模更具性价比**。

- 实验 7-4 ★★（自己训练 VLM）：视觉编码器（如 CLIP，参数固定）+ 投影层（轻量级，唯一从头训练的部分，充当视觉特征与语言模型的"翻译官"）+ 语言模型。训练用"冻结 LLM + 只训练投影层"策略避免灾难性遗忘；预训练对齐后再解冻 LLM 用高质量图像-描述对做 SFT。范式：**复用单模态预训练成果，通过训练轻量投影层实现跨模态对齐**——高效可扩展，但投影层表达能力有限可能成为跨模态深层理解瓶颈。（VLA 模型是同一骨架再延伸一步让模型输出动作。）

- 实验 7-5 ★★（继续预训练学习新语言）：Mistral 7B v0.3 通过韩语维基百科继续预训练注入韩语能力。关键工程点：**混合数据（约 80% 韩语 + 20% 英语）缓解灾难性遗忘**——目标语言占比过高导致原语言退化、过低学习效率不足。最后用韩语指令数据做 SFT。结论（本章末完整图景再用）：**要让模型记住大量新领域知识，靠的是继续预训练而非 SFT**。

- 三个实验共同规律：预算受限时，算法改进与架构创新比单纯扩大规模更具性价比；预训练赋予的是描述性知识与语言建模能力，缺乏结构化指令遵循和任务导向行为——这正是 SFT 需要填补的空白。

## 4. SFT（监督微调）



- SFT 核心价值不在于注入新知识，而在于**固化协议**：把映射关系、交互格式、风格规范写入参数，使推理时无需冗长提示即可产出符合预期的输出。通常数千到数万条高质量样例即可建立基本对话能力与指令遵循。高效率可能以依赖训练分布为代价（需要探索多种正确策略或部署分布偏离示范数据时，SFT 可能偏向复现示范模式、新场景性能下降）。

- **SFT 数据从哪来**（工业界三条路，经常组合）：①**人工专家示范**——质量天花板最高但贵且慢，适合定义格式与风格的"种子数据"；②**教师模型生成**——合成数据，强模型批量产出"输入—输出"对、过滤后蒸馏给学生（实验 7-8、7-9）；③**模型自举**——模型自己对同一问题采样多条候选，用验证器筛出正确样本再反过来训练自己（拒绝采样微调）。组合套路：少量人工种子立格式 → 教师模型放大规模 → 拒绝采样拉齐质量。构造流程：定义任务分布与输出 schema → 批量生成候选 → 规则校验/格式检查/人工抽检做质量过滤 → 去重、平衡配比、保证多样性。**量级不必贪多——与其堆十万条脏数据，不如精修一万条干净数据：数据里的每一处噪声，SFT 都会忠实地写进参数**。

- 实验 7-6 ★★★（语音 SFT——从"声音复制"到"副语言建模"）：Orpheus（把声音波形压缩为 token 序列，拼接同一说话者参考音频实现跨句音色一致）；Sesame（把笑声、叹气等副语言现象抽象为 `<laugh>`、`<sigh>` 等特殊标记）。SFT 在表达型任务中固化的是风格控制协议与结构化表达习惯，而非事实知识或复杂思考。常见失败模式：训练数据说话者过少导致所有人一个腔调；标记过拟合产生"机械笑"。

- 实验 7-7 ★★★（多语言思考）：大多数思考模型只会用英语"思考"。对 gpt-oss-20b 做 SFT：系统指令加 `reasoning language: German`，用英语/西班牙语/法语等几种语言思考样例训练——**训练数据完全没有中文，但训练完成后设 `reasoning language: Chinese` 模型就能用中文完整思维链思考（零样本跨语言泛化）**。关键：这不是 SFT 本身的泛化能力——多语言预训练已在模型中建立跨语言共享表征空间，SFT 只是激活了预训练时已有的跨语言能力。

- 实验 7-8 ★★（Prompt 蒸馏）：把"长提示 + 思考型教师"的行为压缩到"短提示/无提示 + 非思考学生"。训练数据只保留用户输入与最终结论，丢弃冗长提示与中间思考——学生学会"直接给出结论"，延迟与费用显著降低。两个维度："大到小"（中小模型替代大模型）和"思考到非思考"（同等规模下把显式 CoT 折叠为隐式参数化知识，获得 **20-30 倍响应速度提升**），经常同时使用。**注意：蒸馏会继承教师的边界**——教师在长尾分布有系统性错误则学生硬编码这些错误；教师依赖工具保证正确性时单纯输出蒸馏会失去工具带来的鲁棒性。工程启示：产品形态稳定、输入分布可预期、成本约束明显时 Prompt 蒸馏很好；探索期或任务未定型时保留显式思考与可编辑提示工程仍是快速试错核心。

- 实验 7-9 ★★★（思维链 CoT 蒸馏）：把强教师模型的完整思考轨迹转移给学生模型。同等参数量下可恢复教师 70%-80% 能力——不追求刷新前沿但寻求自主可控模型的团队，这是最务实的跟随者策略（DeepSeek-R1 开源蒸馏小模型为代表）。

  - **"思维围墙"现象**：闭源思考模型（OpenAI o 系列、Gemini）在输出前对 CoT 改写或摘要，最有价值的原始思考被隐藏在 API 之后（防蒸馏、安全、产品体验考虑）——本实验选开源思考模型作教师（DeepSeek V4、Kimi K3、GLM 5.2 直接公开完整思维链）。

  - **实验现场：模型会写代码，不代表它愿意帮助你蒸馏模型**。作者最初用 GPT-5.6-Sol 驱动的 OpenAI Codex 编写实验代码，任务明确涉及模型蒸馏时 Codex 拒绝继续；切换到 Claude Opus 5 驱动的 Claude Code 也遇到同样拒绝；最终用 Kimi K3 完成。蒸馏与正常 SFT 技术上高度相似，但在厂商安全与产品策略中可能与模型提取、能力复制、知识产权保护联系起来。**注意：不能简单解释为"Claude 不提供思维链"或"Kimi 安全护栏更弱"**——API 是否返回 summarized thinking、Coding Agent 是否愿意实现蒸馏程序、服务条款是否允许模型输出用于训练是三个不同问题。

  - **更实际判断：对绝大多数做后训练的人，根本不需要去蒸馏闭源模型的思维链**——当前最先进开源模型与 SOTA 闭源模型差距没想象中大；教师只需"明显高于学生"不需"全球第一"；后训练 200B 及以下规模模型用开源 SOTA 当教师完全够用。

  - 三步流程：①采集轨迹（目标任务分布采样问题，开源教师生成完整"思考+答案"轨迹，**规则验证器过滤掉最终答案错误的轨迹**——否则错误思考过程被学生一并模仿；这叫**拒绝采样 Rejection Sampling**，用它构造数据做 SFT 即**拒绝采样微调 RFT**——介于纯 SFT 与 RL 之间，不训奖励模型不做策略梯度，只靠"拒绝错的、留下对的"提升数据质量，可验证任务上性价比极高）；②SFT 训练（"问题 → `<think>` 思考轨迹 `</think>` + 最终答案"为训练对）；③对比评估（蒸馏前后对比，衡量能力恢复比例）。验收：数学/代码基准显著提升且思考轨迹出现教师式反思、回溯、验算行为。代价：学生会继承教师的系统性错误和冗长思考习惯（后者可结合实验 7-10 的 AdaptThink 思路二次优化）。

- 四个 SFT 实验共同特征——"把稳定的映射与协议写进参数"：语音 SFT 固化风格控制协议、多语言 SFT 固化思考组织模板、蒸馏 SFT 固化输入到输出的直接映射。目标越明确、格式越清晰、评估标准越稳定，SFT 越能以很高样本效率提升性能。

## 5. 何时选择 SFT，何时选择 RL



- **SFT 适用**：格式固化（JSON 输出、对话风格）、拥有高质量专家示范、训练与部署环境高度一致。

- **RL 适用**：实际部署环境与训练环境存在系统性差异且能构造反映差异的可靠奖励（训练时 J/Q/K 都是 10、部署时变 11/12/13）、需要探索最优策略（专家示范本身不一定最优）、标注成本过高无法为每条路径提供示范。

- 结构化输出不稳定时最稳健策略是"先 SFT 后 RL"两阶段（SFT 目标不是追求任务性能极致，而是建立输出格式稳定性）。边界条件："较小基础模型 + 严格结构化输出"设定；DeepSeek-R1-Zero 证明足够强的基础模型可跳过 SFT 直接 RL。

- **实际决策顺序**：①先问"需要后训练吗？"——Harness 工程（优化 prompt、工具设计、上下文管理）能解决就不训练模型，**大多数 Agent 应用落在这里**；②需要训练先试 SFT——固化输出格式（JSON schema、API 调用格式）、固化协议性知识（术语用法、输出格式、流程习惯）、统一风格（语气、长度）；**但 SFT 不适合注入大量事实性知识（"知道什么"）——那需要继续预训练或交给 RAG**；③SFT 不够时加 RL——需泛化到新场景、探索最优策略、标注成本过高；输出尚不稳定先用 SFT 或约束解码稳定格式再 RL；强基础模型已满足格式要求可直接 RL。

## 6. 单轮强化学习：记忆与泛化的对照



- "单轮"指任务在一次交互中完成（接收输入、产出输出、获得奖励），无跨步骤状态。单轮场景提供清晰对照条件：相同任务、相同基础模型、相同计算预算，唯一变量是训练方法。

- RL 最小直觉（完整公式在 7.8 节）：策略梯度——对同一问题多生成几条回答，奖励高的提高出现概率、低的降低。**PPO** 在概率比超出指定区间时裁掉代理目标中的额外收益（抑制大幅更新，但不是对策略变化的硬约束；带价值网络的 PPO 用价值网络估计基线算出更细优势）；**GRPO** 不训练价值网络，用"同一问题多条回答互相比较"判断相对好坏。

- 实验 7-10 ★★（AdaptThink——学会"何时不思考"）：大型思考模型（o1、DeepSeek-R1）对所有问题生成冗长思维链，简单问题上不必要开销。先验证直觉：NoThinking 模式简单问题上性能相当甚至更好，困难问题 Thinking 优势才显现。AdaptThink 通过 RL 训练模型自适应选择模式，两个核心组件：**约束优化目标**（鼓励 NoThinking 同时确保整体性能不下降）+ **重要性采样策略**（平衡 Thinking/NoThinking 样本，解决冷启动——训练初期模型几乎只产生 Thinking 样本、NoThinking 分支学不起来）。历史训练记录（checkpoint-free，8×H100，step 0→300）：MATH500 准确率 0.8100→0.8180（+0.80 pp）、响应长度 -67.90%；GSM8K 0.796816→0.818802（+2.20 pp）、长度 -53.44%；AIME mean@16 0.314583→0.310417（-0.42 pp）、长度 -47.17%；NoThinking 比例 83.80%/84.15%/56.25%——**存在与难度一致的路由信号，但不能称为逐题"完美难度感知"，也不能声称准确率普遍提升**。与 Prompt 蒸馏互补形成"快-慢双系统"：蒸馏降低需思考的任务比例，AdaptThink 优化剩余任务触发策略。

- 实验 7-11 ★★（GeneralPoints——单轮 RL 的"记忆与泛化"对照）：Chu 等人 2025《SFT Memorizes, RL Generalizes》（arXiv:2501.17161）提出的算术思考卡牌游戏（类似"24 点"，四张卡牌数字通过加减乘除凑出 24，每数字恰好用一次）。规则变体 GP-L（训练 J/Q/K=10、测试 11/12/13）；视觉变体 GP-VL（训练黑色花色 ♠♣、测试红色花色 ♥♦）。基于 Llama-3.2-Vision-11B，先 SFT 初始化再在相同预算下扩展 SFT 与 RL（带价值网络 PPO）。**结果**：规则 OOD——RL 在 GP-L +3.5%（11.5%→15.0%）、SFT 下降 8.1%（11.5%→3.4%）；GP-VL 上 RL +3.0%、SFT -5.6%。视觉 OOD——RL 在 GP-VL +17.6%（23.6%→41.2%）、SFT -9.9%（23.6%→13.7%）。追踪视觉识别准确率：**RL 通过结果导向优化改善底层视觉编码器、与整体性能高度相关；SFT 过度拟合思考过程 token 模式、忽视视觉 token 学习，识别准确率反而下降**。另有发现：未经 SFT 直接端到端 RL 完全失败（基础模型无法产生结构化输出、奖励无法计算——特定设定结论非普适）；**验证迭代次数越多泛化越好（10 次 +5.99% vs 1 次 +0.48%），增加测试时计算量是泛化提升的重要因素**。解释：有限 SFT 数据强化"遇到 J/Q/K 就当 10 用"的固定模式；结果导向 RL 强化"重新计算直到得到正确答案"的策略。

## 7. RLHF：从人类偏好到奖励模型



- 前面实验前提：任务有可验证对错，规则验证器就能打分。但当前部署对话模型"像一个得体、安全的助手"靠的是另一条更早成熟的路线：**RLHF（Reinforcement Learning from Human Feedback）**。

- **InstructGPT 三段式管线**（OpenAI 2022，沿用至今的标准流程）：

  1. **SFT**：人工示范"指令—回答"对微调，建立基本指令遵循能力；

  2. **训练奖励模型（RM）**：同一提示让模型生成多个回答，人类标注员两两比较标出更偏好哪个。训练目标基于 Bradley-Terry 模型：L_RM = -log σ(r(x,y_w) - r(x,y_l))——让 RM 给被偏好回答打更高分。**采集比较而非打分的原因**：人类很难一致给出绝对分数（"这个回答值 7.3 分"几乎无法标注一致），但"A 和 B 哪个更好"判断可靠得多。"奖励模型"是本章一条暗线——这里是人类偏好学出的打分器；7.10 节有各种变体（ORM/PRM/生成式奖励模型）；当对错能用规则直接判定时，"奖励模型"退化成一端确定性代码（RLVR）；

  3. **用 RM 打分做 PPO**：以 RM 分数为奖励信号对 SFT 模型做 PPO 训练。

- **KL 惩罚：别离出发点太远**。实际优化奖励 = r_RM - β·KL(π_θ || π_ref)。四个问题讲透：

  1. **KL 散度是什么，惩罚加在哪里**：衡量两个概率分布差异（越像越小、相同为 0）。比较当前策略 π_θ（正在训练的模型）与参考策略 π_ref（训练起点，通常是 SFT 模型）在相同前文下生成的回答分布。β（kl_coef 超参）控制惩罚力度；

  2. **方向为什么"当前策略在前"**：KL 不对称。KL(π_θ||π_ref) 在把参考分布视为目标、当前策略视为近似分布的惯例下称**反向 KL（reverse KL）**——按当前策略高概率生成的回答衡量与参考策略的对数概率比，直接抑制追逐奖励的策略过度偏离起点；

  3. **mode-seeking 何时出现**：用受限分布族近似多峰目标分布时，反向 KL 对低概率区域分配质量施加较大代价，可能表现出集中到单一模式的倾向。但 RLHF 同时优化奖励项与 KL 正则，实际多样性还取决于奖励模型、KL 系数、采样方法与策略表达能力；

  4. **不加会怎样**：**RM 是在参考策略附近输出分布上训练的，模型被优化到 RM 没见过的分布上，RM 打分就成了没有依据的外推**。KL 惩罚同时防两件事：reward hacking（钻奖励漏洞刷高分）和分布崩塌（输出退化成重复、乱码等极端形态）。即便 RLVR 训练中 KL 正则也常保留（DAPO、Open-Reasoner-Zero 等少数工作有意去掉——注意 DeepSeek-R1-Zero 的 GRPO 本身仍显式包含 KL 项）。

- **奖励模型会被"过度优化"**：RM 终究是人类偏好的代理指标（proxy）。Goodhart 定律：一个指标一旦成为优化目标就不再是好指标。OpenAI 系统测量**奖励模型过优化（reward model over-optimization）**：随 RL 推进，代理奖励（RM 分数）单调上升，真实质量（人类评估）先升后降——模型逐渐学会"让 RM 打高分"（冗长、讨好、貌似严谨的空话）而非"更好地回答"。KL 惩罚与早停是最常用缓解手段。

- **DPO（Direct Preference Optimization）**：既然"训练 RM + PPO"组合最终效果是"提高被偏好回答概率、压低被拒绝回答概率、同时不离参考模型太远"，不如跳过显式 RM，把偏好对直接变成带隐式奖励的分类损失——**数学上可证明等价于带 KL 约束的离线偏好优化，奖励模型被隐式藏进策略本身**。训练像 SFT 一样简单（不需在线采样、价值网络、单独维护 RM）。代价：**完全离线**——无法探索偏好数据之外的新行为，性能天花板由偏好数据质量与覆盖面决定。

- **RLHF 与 RLVR 的关系**：差别在奖励从哪来——RLHF 奖励来自学习到的 RM（背后人类偏好数据），RLVR（可验证奖励强化学习）奖励来自规则验证器（测试是否通过、答案是否正确）。Agent 任务大多可验证，本章以 RLVR 为主线。**两者不是取舍关系**：实际部署模型叠加使用，RLHF 负责对话质量与安全对齐、RLVR 负责推理与 Agent 能力。后文生成式奖励模型是两条线的汇流。

## 8. 强化学习算法比较



- 最重要的话：**现成的 RL 算法（PPO、GRPO 等）你知道怎么用、能选对就够了，真正决定成败的是数据和环境**。算法已封装进 veRL、TRL 等成熟框架，调用通常只是改几行配置。本节目标是建立"什么场景用什么算法"的选择地图。

- **严格术语**：**在轨策略（On-Policy）**只用当前策略自己新采样的数据更新自己；**离轨策略（Off-Policy）**可以用其他策略（或旧版本策略）产生的数据学习（如前文 Q-learning）。对齐本章方法：SFT 是离轨的模仿学习（数据来自教师或人类示范）；PPO、GRPO 用于 LLM 训练的标准形式是在轨的（每轮用当前模型新采样的 rollout 更新）；DPO 是离线的偏好优化。

- 算法基础：策略梯度（REINFORCE）——朝着"能提高期望回报的方向"调整策略参数；直接用整条轨迹回报 G 无偏但方差大，引入基线 b 改用**优势（Advantage）Â = G - b** 降低方差。PPO 与 GRPO 本质是在"如何稳定估计并使用优势"上给出的两类改进。

  - **PPO**：用"裁剪"在概率比超出区间时截断代理目标中额外收益，抑制大的策略变化——但它不保证实际概率比或整体策略距离落在硬边界内；

  - **GRPO**：省去价值网络（PPO 里额外训练辅助神经网络给轨迹每步估计价值函数、算出更细优势），改用"组内相对比较"：对同一问题采样 N 条轨迹，每条优势 = 它在组内的相对表现（比组内平均好为正、差为负）。上式省略了 KL 正则项，实际训练通常还要加 per-token KL 惩罚。

- 表 7-4 主流方法对比：



| 方法 | 类型 | 核心思路 | 优势 | 劣势 | 适用场景 |

|---|---|---|---|---|---|

| REINFORCE | 在线 RL 算法 | 用整条轨迹最终奖励更新策略 | 实现简单 | 方差大、训练不稳定 | 理论基准；带基线变体（RLOO、REINFORCE++）是当前主流之一，GRPO 本质是带组内基线的 REINFORCE |

| PPO | 在线 RL 算法 | 裁剪概率比超出区间后的代理目标收益 | 稳定，价值网络提供更细粒度信用分配 | 不是策略距离硬约束；需额外训练和存储价值网络，超参数敏感 | 多轮 Agent、长轨迹信用分配 |

| GRPO | 在线 RL 算法 | 对同一问题采样多条轨迹，组内相对比较 | 无需价值网络，成本低 | 优势按整条回复均摊，信用分配粗糙；依赖组内奖励有区分度 | 单轮/短轨迹任务，奖励区分度好的场景 |

| DPO | 离线偏好优化 | 偏好对直接变成带隐式奖励的分类损失 | 极简高效，不需在线采样 | 无法探索新策略，受限于离线偏好数据 | 已有高质量偏好数据 |

| KTO | 离线偏好优化 | 仅需给单个样本打"好/坏"标签 | 标注成本极低 | 信号粗糙 | 标注资源极有限 |

| Best-of-N | 推理时方法 | 推理时生成 N 个输出选最优 | 不改模型，实施简单 | 推理成本成倍增加，能力不沉淀进参数 | 早期快速提升质量，为 RL 提供收益上界估计 |



- 本章实验各自所用算法：GeneralPoints 与 V-IRL 用带价值网络的 PPO；AdaptThink 用自定义约束优化目标 + 重要性采样；ReTool 用基于 veRL 改造的 PPO；SimpleVLA 与 RLVP 基于 GRPO。

- 实践选择路径：有可靠奖励信号且有计算资源 → GRPO（简洁）或 PPO（灵活，长轨迹信用分配更细）；有高质量偏好数据 → DPO/KTO；早期探索阶段 → Best-of-N 快速起步。**大多数情况下哪个都行——先别在算法上纠结**。

## 9. 数据与环境：比算法更重要的事



- 全章最想让人记住的一节（主线二正面陈述）。算法重要性远不及三个更基础要素：**仿真环境的保真度、训练数据的质量、基础模型的能力**。呼应第六章结论（评估与仿真环境是后训练基石）和 OpenAI 认知反转（先验 > 环境 > 算法）。

- **环境：模型练习的场地**。环境失真策略必废——仿真里客服总按固定套路回话、错误信息跟生产对不上，模型学到一套只在仿真里管用的"应试策略"，一上线就露馅（RL 项目最常见的翻车方式）。**构建高保真环境常常比训练本身更贵更难**——真实 API 有速率限制、会封号、有副作用，必须造稳定可控可重放的"影子世界"。环境的另一半是奖励函数——奖励设计是环境工程的一部分。

- **造不出环境怎么办：让模型扮演环境**。两个层次：

  - **模型合成工具调用的返回值**：ZeroSearch（2025）用一个 LLM 扮演搜索引擎——学生发 query、模拟引擎生成检索结果；**课程式设计**——训练初期返回高质量强相关文档，随训练推进逐步掺入噪声降低质量，逼学生学会在真实搜索引擎不完美的返回里提取有用信息。最终训练全程没见过真实搜索引擎的模型直接对接真实搜索依然表现良好；

  - **模型仿真整个环境的动态**：DreamGym（2025）把环境动态蒸馏进一个推理式"经验模型"——给定当前状态与动作逐步推理状态转移和反馈信号，不访问真实环境批量合成 rollout 用于在线 RL。客服/销售类 Agent 训练普遍用 LLM 扮演用户（用户模拟器，τ-bench 同思路——**同一个模型模拟器，既能当考场也能当练习场**）。

  - **必须指出风险**：模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收；**RL 会主动寻找并利用模拟器的漏洞进行 reward hacking**。工程稳妥做法是混合：模型模拟承担大部分交互量，辅以真实环境交互，并用真实环境交互定期校准模拟器偏差。

- **数据：最关键的一环，质量胜过一切**。SFT 阶段指示范样本、RL 阶段指任务分布和奖励信号。铁律：**数据质量胜过算法**——再精巧的算法喂脏数据也只能学出脏策略（SFT 一字不差把噪声偏见固化进参数；RL 朝有偏差奖励拼命优化，错误方向越走越远）。

- **很多场景下，只要 SFT 数据质量到位，根本不需要做 RL**。RL 又贵又不稳定（常是 SFT 几十到上百倍成本）。RL 不可替代的场景有限（见 7.5）：部署分布系统性漂移、专家示范不是最优、标注成本高到无法为每条路径示范。**先把 SFT 数据做好，再判断到底需不需要 RL**。

- **Anthropic 案例**：2025 年之前后训练配方主要是海量高质量 SFT + RLAIF（Constitutional AI 的"基于 AI 反馈的强化学习"，用一部"宪法"引导模型自己给回答打分做对齐），不怎么依赖 RLVR——但当时 Coding 模型质量已非常出色。**当 SFT 数据足够好时，一套并不花哨的配方也能训出顶尖模型**。2025 年以来 Anthropic 明显加大 RL 投入——**数据决定你能到哪，RL 决定你还能再高多少**。

- **数据质量三个维度**：**覆盖面**（部署时会遇到的各种情况，尤其长尾和边界）、**多样性**（说话者、风格、解法够不够丰富，否则模型塌缩到单一模式）、**标注准确性**（示范答案本身对不对——思维链蒸馏里错误思考过程会被学生一并模仿，所以实验 7-9 用规则验证器先过滤错误轨迹）。投入产出比远高于换更花哨的算法。

- **拒绝采样是把"标注准确性"拉满的标准动作**：每条提示采样 k 条候选（k 常取 4 到 16）→ 规则验证器/单元测试/参考答案判对错（无自动验证器可用奖励模型或强模型打分）→ 只保留通过筛选的轨迹、去重、限制同一提示保留条数（防数据向少数简单题塌缩）→ 用留下数据做一轮 SFT。模型变强后重新采样再筛迭代（STaR、RFT 一类自举方法的核心循环）——不需要新算法，只需要可靠验证器和足够采样预算。

- **进一步：让 Agent 改变题目分布本身**。Autodata 的 Agentic Self-Instruct：主 Agent 协调四个角色——challenger 生成任务、弱求解器和强求解器分别尝试、verifier 判断答案质量并反馈出题环节，寻找"强模型能解决、弱模型仍有困难、评价器又能可靠判断"的任务。**与动态采样不同：动态采样改变预算分配，Agentic data generation 改变任务分布**。"自我改进"需谨慎界定：只训练弱求解器而强求解器和出题机制固定时更接近自适应蒸馏；只有出题 Agent 也根据下游训练效果继续优化才形成完整元层闭环——仍属前沿探索，不应当作成熟通用配方。

- 第九章呼应：语音识别"该不该收话"总在摇摆的根源不在模型结构，而在训练标签用"上帝视角"标的——把标签改成"只用决策当下能拿到的信息"问题就消失。**很多时候，数据比架构更关键**。

- **什么时候才轮到算法**：合理用力顺序——**先选强基础模型 → 再把环境和数据打磨到位 → 最后才在算法和超参上做边际优化**。环境和数据没做好就卷算法是南辕北辙。

## 10. 从单轮到多轮：信用分配与奖励设计



### 10.1 多轮任务的核心挑战



- 复杂性质的跃迁：策略不仅要选当前最优动作，还要考虑未来状态价值；不仅处理即时反馈，还要在延迟奖励下做**信用分配（Credit Assignment）**（10 轮对话解决用户问题，好评该归功于第 2 轮精准提问还是第 7 轮耐心解释？）；多轮还引入**部分可观测性**（无法获得完整状态，必须通过历史观测构建隐含状态表征）。

- 多轮交互的物理形态正是第一章和第四章的 ReAct 循环——每轮一次思考→行动→观察迭代，奖励延迟来自"最终结果好坏要多轮之后才能判断"这一结构性约束。



### 10.2 奖励信号的密度与范式



- 奖励信号两个设计维度：**密度**（多久给一次反馈——二元/稀疏/过程奖励）和**表示形式**（反馈长什么样——标量/向量/生成式）。

- 评估环境与训练环境："评估环境可以复用"不等于"这一份评估数据可以直接拿去训练"。三个例子：SWE-Gym 基于 SWE-bench 构建可训练任务集（问题描述作为输入、patch 作为监督、测试用例提供奖励）——但被拿去训练的是**新构建的任务集**，SWE-Bench Verified 这 500 题评估子集必须与训练数据严格隔离；τ²-bench 完整轨迹记录为模仿学习提供宝贵数据（成功轨迹正样本、失败轨迹经标注后负样本）；AndroidWorld 参数化模板批量生成变体、自然支持课程学习。

- **二元奖励的适用场景**：有明确正确答案的任务（数学题、SQL 查询）——简单可靠，不需要更复杂设计。问题出在没有明确正确答案的开放式任务。

- **稀疏奖励的困境**：Pine AI 打电话办事例子——用二元奖励训练联系 Xfinity 修改套餐，100 次尝试才偶然成功。根源（Silver 与 Sutton《Welcome to the Era of Experience》）：**当前 RL 方法只能从最终成败结果学习，无法从环境给出的丰富反馈中学习**。客服明确说了"需要信用卡后四位"，人类听到一次就记住，RL 只看到最终结果"失败"。10 步流程前 9 步完美、第 10 步出错，信号也只是"整个任务失败了"。

- **过程奖励（Process Reward）**：对执行中每个关键步骤即时反馈，将评估从黑盒转向白盒（代码生成中分别评价需求理解、搜索代码、设计方案、编写代码、运行测试；客服中检查身份验证、查询信息、确认、支付）。挑战：标注成本高、可能过度约束创新性——实践中需与结果奖励协同。

- **奖励范式演进**（DeepSeek 研究 + 本书补充向量维度）：沿用 Pine AI 场景（任务完成但有瑕疵——遗漏账单地址、误报套餐名称）：

  - **标量范式**：7.2 分——无诊断能力；

  - **半标量范式**：先分析优缺点再给 6.5 分——有依据但信息量有限；

  - **向量范式**（本书补充）：多维度分别打分（信息查询准确性 9/10、信息收集完整性 6/10、沟通流畅度 8/10、沟通准确性 7/10、用户沟通准确性 10/10、整体任务完成度 8/10）——像体检报告精确定位问题（"信息收集"只有 6 分，说明应重点优化收集环节的 prompt）；

  - **生成式范式**：用自然语言详细描述，支持多次采样从不同角度分析。**DeepSeek 论文真实结论：生成式奖励模型可通过推理时扩展（多次采样评价再汇总）持续提升评判质量，在多个奖励模型基准上超越仅靠扩大模型规模的标量方案**——核心价值在于把环境丰富反馈转化为可学习知识，使 Agent 从一次失败就能学到改进方向，而非数百次盲目试错。

  - 从 RLHF 视角：生成式 RM 可视为 Bradley-Terry 判别式 RM 的演进（判别式只输出标量分数、生成式用自然语言生成带推理的评判，把"为什么好、为什么差"讲出来）——更透明，更容易扩展到规则和标量分数难覆盖的开放任务。

  - **选择哪种奖励函数取决于任务的验证方式**：答案可用代码自动验证（数学题、单元测试）→ 二元奖励最简单直接；多个独立质量维度（客服的信息准确性、沟通礼貌度、问题解决率）→ 向量奖励分维度评估；任务高度开放难以拆分维度（创意写作、复杂对话）→ 生成式奖励让评判模型给出定性分析。

- **生成式奖励模型的训练**（DeepSeek 三步）：①模型为具体任务自动生成评价原则（"优秀 Agent 应该：查到正确官方客服渠道；收集齐全身份验证信息；电话沟通中准确转述用户需求；避免编造或误述信息；处理客服要求时响应及时"）；②根据原则逐条评价执行过程；③系统自动检查评价准确性（模型说"准确转述了套餐名称"但实际轨迹显示说错→负反馈；准确识别遗漏账单地址→正反馈）。数千案例练习后模型学会为不同任务制定合理原则并准确诊断。优势：**泛化能力强**（学会的是"定标准、做评价"的元能力而非固定评分表）；**评价过程透明、便于审查偏见**（发现模型总把"回复长"当优点就知道它错误地把长度当质量）；**支持奖励模型与策略模型协同进化**（而非传统方法奖励模型固定不变）。



### 10.3 过程奖励 vs 结果奖励：多轮任务的关键选择



- 多轮任务还面临**长距离依赖**问题（早期决策如子目标设定、工具选择的影响可能数十步后才显现）。

- 过程奖励每一步给反馈（降低信用分配难度，但引入人工设计偏见、可能限制探索空间）；结果奖励只在终点给反馈（最大探索自由度，但训练难度和样本需求更高）。比方：过程奖励像老师逐题批改作业（快速知道错哪），结果奖励像只看期末考试成绩（自由探索但反馈很晚）。

- 术语：**过程奖励模型（PRM）**对推理/执行每个中间步骤打分（代表：OpenAI《Let's Verify Step by Step》——逐步骤人工标注训练的 PRM 在数学推理上显著优于只看最终答案的监督）；**结果奖励模型（ORM）**只评估最终结果。**RLVR 中的规则验证器可以看作 ORM 的特例**——把"学习到的打分模型"换成确定性规则。

- **实践中的信用分配**：折扣因子 γ 在多轮 LLM RL 中通常直接设为 1（任务只有几轮到几十轮、优化目标就是最终成功与否）；PPO 依赖 **GAE（广义优势估计）**（用价值网络对每步估计"比预期好多少"，偏差与方差加权折中）；GRPO 把整条 response 视为单一动作、轨迹级优势均摊到所有 token（第 2 轮精准提问和第 7 轮无效寒暄拿完全相同信用——单轮短任务问题不大、长程多轮稀释学习信号，这正是带价值网络的 PPO 在多轮场景仍有价值的原因）；介于两者之间是 **turn-level 分摊**（以"轮"为单位计算优势，比 token-level 便宜、比轨迹级精细——当前多轮 Agent RL 框架常见折中）。

- 实验 7-12 ★★★（V-IRL-VL 空间思考——过程奖励）：开放世界视觉导航环境（真实城市街景）。训练用纽约 1000 条路线，测试用米兰、新德里、伦敦、香港等九城市 18 条路线。规则变体：训练用绝对方向（north/east）、测试用相对方向（left/right）；视觉变体：跨城市。**结果（再次呈现"SFT 记忆、RL 泛化"模式）**：规则 OOD——RL 在 V-IRL-L +11.0%、SFT 下降 79.5%；V-IRL-VL 上 RL +9.3%、SFT -33.2%。视觉 OOD——RL 从 16.7% 提升至 77.8%（+61.1%），**端到端 RL 用开源模型超越依赖闭源模型精心提示工程的强基线**；SFT 降至 11.1%。**过程奖励扮演关键角色**：正确动作 +1、错误动作 -1、地标识别错误额外 -1.5——密集反馈降低长时序信用分配难度（第 5 步走错立即负反馈，不用等第 20 步结束）。配合验证重试机制（verify_iter=2）。追踪视觉识别准确率：RL 优化"给定识别结果后的决策"还改善"视觉识别本身"（结果导向优化信号反向传播到感知层）；SFT 倾向在思考层过拟合、忽视感知层学习。**SFT 与 RL 协同的微妙平衡：SFT 应训练到"格式稳定、能力初具"即可，不宜恋战**（SFT 过度训练严重过拟合时 RL 也无法恢复 OOD 性能）。

- 实验 7-13 ★★★（SimpleVLA-RL——结果奖励）：VLA（视觉-语言-动作）模型统一视觉感知、语言理解与动作生成（机器人操作范式）。挑战：扩展 SFT 需大规模人工操作轨迹（收集成本极高且多样性受限）、有限场景训练的模型遇到未见任务/环境/物体性能显著下降。SimpleVLA-RL 基于 veRL，**仅用二元结果奖励（成功/失败）**，三项探索增强：动态采样过滤全成功/全失败组（稳定梯度）、更高裁剪界 [0.8, 1.28]（鼓励探索）、更高温度 1.6（生成多样化轨迹）——三项组合 300 步内提升约 30%。**LIBERO 报告 97.6%**。**冷启动实验：每个任务仅 1 条轨迹 SFT（17.3%），加 RL 后达 91.7%（+74.4 个百分点，相对提升约 430%）**——有力证明 RL 在数据稀缺下的强大能力。**训练中涌现"推切"（pushcut）——RL 自主发现的新动作模式，从未在人类演示中出现**（标准演示"接近→抓取→垂直抬起→水平移动→放下"，RL 发现"接近→抓取→保持低位→水平推动→完成"，省去抬起步骤、更快且对精确定位要求更低）。框架用 GRPO + 动态采样（仅保留成功率适中的任务，自然形成课程学习）+ 动作分块（一次推理生成未来多步动作，控制线程依次执行、GPU 后台异步生成下一批，只要推理时间小于执行时间机器人就能保持连续流畅运动）。泛化提升多维度：空间泛化、物体泛化、目标泛化。**与 V-IRL-VL 对照看出两种奖励设计的取舍**：结果奖励信号更稀疏但给更大探索自由度（"推切"就是这样发现的）；过程奖励密集反馈加速收敛但可能限制策略跳出演示空间——**当中间步骤的正确性容易定义时过程奖励更高效；当最优路径未知时结果奖励更有潜力**。



### 10.4 奖励结果，约束过程：验证路径惩罚（RLVP）与部分奖励



- **问题：有一类约束，结果奖励不但学不会，还会反向激励违反**——与结果无关的约束（outcome-neutral constraints）：不要反复拨打已明确拒接的用户、不要在非工作时间擅自行动、不要跳过身份验证、不要执行 rm -rf 破坏性命令、不要为让测试通过去改测试文件、不要覆盖自己都没读过的文件。**违反这些约束往往让"表面成功率"更高**（抄近路更快：直接改测试文件比真修 bug 更快通过）——纯结果奖励主动激励 Agent 违反。论文里只用结果奖励训练的 Agent 几乎每一局都会踩线。

- **核心洞察：真实环境是"不对称的验证器"**——可机器判定环境（终端、代码库、定理证明器）里，很容易验证"某个动作是不是坏动作"（坏动作有明确确定的特征），很难验证"Agent 是否在朝目标取得有意义进展"（几乎和"解决任务"一样难）。**环境能可靠提供的密集信号，本质上是"路径上的惩罚"，而不是"进展上的奖励"**。

- **做法**：在结果奖励之外加一路可验证"路径信号"：**R = O + β·Φ**。O 是结果奖励（稀疏，仍是真正目标）；Φ 是路径信号，由**确定性规则引擎逐动作给出**（对"动作 + 动作发生前状态"的纯函数判断，不是学出来的裁判模型）。Φ 两种用法：**惩罚（-λ）**——每出现一次可机器判定的违规动作（破坏性命令、改测试文件）在该动作 token 上扣 λ 分；**守规奖励/部分奖励（+μ，Partial Credit）**——每出现一次可验证的好动作（满足前置条件、达成子目标、通过测试数变多、待证目标数变少）加 μ 分。两路信号各自归一化再合并（避免密集路径信号淹没稀疏结果信号）。直接接 PPO/GRPO 训练循环：不改优化算法，只重塑每步奖励。

- **为什么有效——统一解释：组内方差（within-group variance）**：GRPO 优势本质就是组内方差——一组里每条 rollout 奖励完全一样时方差为零、每条优势都是零、这组样本贡献不出任何梯度。纯结果奖励的"零方差死局"在两种情况必然发生：**全败组**（训练早期：任务太难全部失败、O 全 0→零方差→无梯度）和**全胜组**（训练后期：任务快学会全部成功、O 全 1→同样零方差）。**纯结果奖励在成功率的两个极端都是"瞎的"**。（社区以前把零方差组直接丢掉——DAPO dynamic sampling 丢全对全错 prompt；RLVP 换问法：与其丢掉，不如问什么样的密集信号能补回缺失的方差。）

  - **可验证的惩罚永远能补回方差**：全败组"失败得规不规矩"通常各不相同（有的跑了破坏性命令、有的没有）——惩罚一加全败组内部立刻有差异、梯度活了。坏动作总是便宜可查，惩罚是"永远可达"的那半个解；

  - **可验证的进展奖励（Partial Credit）只在"进展可达"时能补回方差**：一组里有的多通过两个测试、有的多证出一个引理→有差异、+μ 能造出方差；但任务太难每条 rollout 进展都卡在零（软件修复里没人能让任何隐藏测试通过）→进展信号处处为零、还是零方差。所以进展奖励是"可达性门控（reachability-gated）"的那半个解。**密集信号只在它能补回结果奖励所缺的组内方差时才有用**。

- **用法一：惩罚路径，换取可部署性——四条设计原则**（每条都堵一个坑）：

  1. **只惩罚可验证的"动作"，绝不惩罚"没进展"**——惩罚靶子必须是具体可机器判定的坏动作（跑了 rm -rf、前置条件没满足就打电话），不是"这一步没进展"（"不做任何动作"正是规避"没进展惩罚"最省事的办法——会把 Agent 教成什么都不干）；

  2. **结果奖励始终是主驱动力，惩罚不能单独优化**——致命的不作为陷阱（inaction trap）：只有惩罚没有结果奖励时最优策略是"什么都不做"（零违规也零成功）；消融显示纯惩罚让成功率在每一个随机种子上都塌到零。必须让结果奖励提供"把任务做完"的拉力、惩罚只负责"怎么做"；

  3. **每个惩罚（-λ）配一个对应的守规奖励（+μ）**——既扣"改测试文件"的分也奖励"真去修 bug 让它自然通过"的合规动作，给 Agent 指一条出路而不是只堵不疏；消融显示去掉配套守规奖励明显拖慢并动摇合规行为养成；

  4. **合规路径必须可达、惩罚靶子必须无法钻空子**——用少量脚本示范先让 Agent 知道"守规的路怎么走"（否则它可能永远探索不到合规动作、+μ 永远用不上）；判定"什么算违规"必须用具体的确定性检查而非学出来的"合规度"评委（否则钻空子问题只是从策略转移到评委）。

- **用法二：奖励可达进展，换取样本效率（Partial Credit）**：同一个 +μ 从"守规奖励"换成"进展奖励"，从"约束过程"变成"加速学习"——全败组里进展可达时 +μ 把零梯度死局变有效梯度，用更少昂贵交互达到同样能力。论文在定理证明（miniF2F）和软件修复上对照：**关键变量是可达性，而不是信号本身是否"密集"**——定理证明每证出一步待证目标数实实在在下降（进展可达，密集进展奖励显著加速收敛且更稳更少发散）；软件修复里一整批 rollout 一个测试都过不了（进展不可达，老老实实用纯结果奖励反而更好）。**可达性可在训练前用少量 base 模型 rollout 测组内方差诊断**。

- **与 RLVR 的关系（点破易混点）**：RLVP 和 RLVR 只差一个字母恰好点出互补——**RLVR 验证的是结果，RLVP 额外验证过程**。叠加得到既盯着"把事办成"、又盯着"办得规不规矩"的训练信号——这正是能安全上线的 Agent 所需要的。

- 实验 7-14 ★★★（RLVP 实验）：在 GRPO 基础上加两路信号（O 结果奖励 + Φ 路径信号，分别归一化后按 R = O + β·Φ 合并）。测试环境：TerminalBench（终端操作，违规如破坏性命令）与 miniF2F（形式化定理证明）。**预期观察**：TerminalBench 上（Qwen3-4B，5 个随机种子）每局违规次数从纯结果奖励的 3.71 降到 0.66（约 6 倍），任务成功率噪声范围内基本持平——"守规"几乎免费拿到，且 Agent 反而做了更多有效动作（并非靠"少做少错"）；miniF2F 代数题（进展可达）达到 0.9 成功率所需迭代数从 7.0 降到 4.4（4B），大模型差距更明显（30B：8.5 → 5.4，且纯结果奖励部分种子直接发散）；链式文件操作任务"全败组"比例从 65% 降到 8%。反例：软件修复"进展不可达"设定下密集进展奖励处处为零并不带来收益——印证"可达性才是门槛"。

## 11. RL 学习工具调用



- 工具使用将 Agent 能力边界从"模型自身推理"扩展到"调用外部系统协作"。三个层次挑战：**第一层学会使用单一工具**（理解输入输出规范、掌握调用时机、处理错误反馈）；**第二层多工具生态中选择**（何时搜索、何时执行代码、何时解析文档）；**第三层工具链编排**（发现工具间依赖关系、识别互斥约束、优化成本效率）。

- 两条活跃路线：**检索增强**（Search-R1，用 RL 训练模型在思考过程中自主决定何时发起搜索、利用返回结果继续推理，而非套固定 RAG 流程）；**软件工程**（SWE-Gym，针对 coding Agent 在真实代码库上做多轮 RL，迭代地编辑、运行、修复代码）。共同挑战：长时序信用分配与环境工程。

- **绕不开的工程细节：对环境反馈 token 做损失屏蔽（loss masking）**——工具调用轨迹里既有模型自己生成的 token（思考、工具调用参数）也有环境返回的 token（代码解释器输出、搜索结果、客服回话）。后者不是策略生成的而是环境给定的——如果计入策略梯度，模型会被训练去"预测沙盒会输出什么"，既偏离优化目标又不稳定。**标准做法：计算损失时把环境反馈 token 屏蔽掉，只对模型自己生成的 token 回传梯度**。这是 ReTool 核心技术点之一（对 `<interpreter>` 标签内反馈 token 屏蔽梯度），也是 Search-R1 所说"对检索到的 token 做屏蔽以稳定训练"，veRL、AWorld 等主流训练框架内置此机制。

- 实验 7-15 ★★★（ReTool——代码解释器增强数学解题）：纯文本思考在精确数值计算、符号操作、复杂方程求解中容易累积误差（连续十步乘法每步都可能算错），代码解释器通过可执行接口实现精确验证。ReTool 把代码解释器实时执行整合进 RL 思考循环。训练两阶段：**SFT 预热（约 1 小时）**把纯文本推理数据转换为代码增强轨迹建立基本工具调用模式；**RL 训练（基于 veRL 改造的 PPO，训练数据取自 DAPO-Math-17k，约 9 天 400 步）**通过交织实时代码执行的 rollout 优化策略——模型生成含 `<code>` 标签代码、沙盒执行后结果包装在 `<interpreter>` 标签反馈、模型继续生成，形成"文本 1 + 代码 1 + 反馈 1 + … + 答案"混合推理序列。每训练步生成 512 个响应（32 问题 × 16 候选），平均每响应 7-9 轮交互，总 token 处理量从 25M 增长到 40M。**AIME 2024 结果**：Qwen2.5-32B-Instruct 第 110 步中间检查点准确率从约 25% 提升至 52%（Best-of-30 达 85%）；400 步后 67.0%，纯文本 RL 基线训练 1080 步只有 40.0%。**涌现能力**：代码自我修正（识别执行错误并自主生成修正版本）、工具调用从后期验证转为早期探索、思考效率提升（长度减少 40% 但准确率不降反升）。前 110 步训练动态三阶段：初期（0-20 步）快速学习基本工具使用（每步 +0.5%）；中期（20-70 步）波动式探索（响应长度 2500→峰值 4700 tokens，策略多样性激增）；后期（70-110 步）稳定收敛（长度回落 4400，性能持续提升波动减小）。

- **DAPO 算法介绍**（Yu 等人 2025，ReTool 训练数据来自 DAPO-Math-17k）：标准 PPO 基础上四项改进，核心目标是防止模型过早收敛到单一策略（只会用一种方式解题）：①**Clip-Higher**（放宽探索上限——标准 PPO 裁剪不是硬边界，过低上界可能限制低概率但有希望的动作；提高正优势对应上界，使模型发现明显更好的新路径时能更大胆提高概率并继续探索）；②**Token-Level Policy Gradient Loss**（让每个 token 权重相等——原始 GRPO 做样本级归一化会让长回答每个 token 被 1/|o_i| 稀释、高质量长链思考得不到足够奖励、冗长重复得不到足够惩罚；改为整个 batch 全部 token 统一归一，长回答按长度获得相称梯度贡献）；③**Dynamic Sampling**（智能分配算力——已稳定解决的简单题减少采样、成功率 20%-80%"可学习区间"的题增加采样，集中算力于最有学习价值的数据）；④**Overlong Reward Shaping**（对超长响应施加软惩罚——生成长思考但没答得更好时降低奖励，引导更简洁高效思考）。

- 实验 7-16 ★★★（AWorld-train——在沙盒中学习使用工具）：GAIA 是最具挑战性的 Agent 评测基准之一（大参数模型大规模训练可能只达约 32%）。本实验用小模型（Qwen3-4B），目标演示完整"从实践中学习"训练流程而非刷新指标。训练环境是 MCP 服务器沙盒：**26 个服务器、126 个工具函数**（Web 交互 Google 搜索/智能浏览器/Playwright、文档处理 CSV/DOCX/PPTX/PDF、多媒体音频转写/OCR/视频摘要、代码执行终端命令/E2B 沙盒、Excel 处理 29 个企业级操作、知识检索 Wikipedia/ArXiv/Wayback Machine）。**真实 API 的速率限制、服务波动、账号封禁使直接在生产环境训练不可行——构建稳定可控可重放的仿真环境是多工具 RL 训练的工程前提**。单工具到多工具质变：单工具只需决定"何时"与"如何"调用；多工具还要解决"调用哪个"与"如何组合"，引入组合爆炸与依赖管理复杂性——工具间有前置依赖（先搜索才能浏览具体页面）、互斥约束（某些工具不能同时调用）、成本差异（不同 API 配额与延迟不同）——**策略需要在这些约束下整体规划，而非贪心地选择当下最优**。

## 12. 提升样本效率的前沿探索



- RL 样本效率低的根源之一：主流策略梯度方法的 **model-free（无模型）特性**——不建模环境动态，难以直接利用单次反馈里的丰富信息。环境每次交互返回的丰富反馈（错误原因、缺少字段、正确流程提示）大部分被浪费（"稀疏奖励的困境"已详细分析）。

- 两条互补思路：①把环境反馈里被浪费的信息重新变成可学习的奖励——**RLVP**（尤其"奖励可达进展"的部分奖励用法，能把全败组里被浪费的采样救回来）；②**On-Policy Distillation**——让每一步训练信号更密集。



### 12.1 On-Policy Distillation：兼得 SFT 与 RL 之长



- 由 Thinking Machines Lab 于 2025 年系统提出并推广，如今是后训练里非常主流的方法。要理解它解决什么，先看 SFT 和 RL 各自的致命短板：

  - **SFT 的短板：Learner-Sampler Mismatch（学习者与采样者不匹配）**——训练数据由"采样者"（教师模型或人类专家）生成，"学习者"只是被动模仿正确路径；学习者自己上场难免犯错、走到训练数据里从没出现过的偏差状态，而它从没见过怎么从这些状态回到正轨，小错累积成大错（只背过标准答案的学生，中间某一步算错完全不知道怎么找回来）；

  - **RL 的短板：信号太稀疏**——RL 让学生自己走（在轨，解决分布不匹配），但每条轨迹走到头只拿一个成败标量，中间每步怎么改还得靠成百上千次试错反推。

  - **一句话对照三种方法：SFT 是"离轨 + 稠密信号"（有分布不匹配）、RL 是"在轨 + 稀疏信号"（反馈稀疏）、On-Policy Distillation 是"在轨 + 稠密信号"（两个短板都补上）**。

- **具体怎么打分**：教师不只判断学生这一步对不对，而是直接给出"在当前这个位置，下一个 token 各种选择分别该有多大概率"的完整分布（学生写到"先查询 API，再解析返回值……"时教师认为"查询"80%、"调用"15%、其余 5%）；学生学习目标让自己在每个位置预测分布尽量贴近教师分布——技术上通过最小化两分布间 KL 散度实现。相比只有最终成败的二元信号，逐 token 分布对齐密集了不止一个数量级。

- **效果**：数学等任务达到同等性能所需训练步数只要纯 RL 的约 1/10。长链思考任务优势尤其明显（每步有教师指路，学生迅速学会纠错）。顺带缓解过拟合（标准 RL 同一 prompt 反复训练容易背下最终答案；这里每次轨迹不同、教师针对具体轨迹反馈，学到的是通用策略而非特定答案，数据复用率大幅提升）。**多轮 Agent 场景价值尤其大**（多轮成败信号在最末端、既稀疏又滞后，逐 token 教师分布恰好补上中间每步缺失指引）。前提（呼应主线）：**必须有一个足够真实的仿真环境让学生自由探索**——否则学生走到教师也没见过的偏差状态时教师打分同样不可靠。On-Policy 的价值建立在"学生真的在部署分布上探索"之上。

- **时间感后训练对照实验（干净验证"稠密信号胜过稀疏信号"）**：第二章状态栏提到的时间感（紧迫度、坚持度、警觉度）推理时靠操作手册就能装上，但要让 8B 小模型脱离提示词、把节奏感写进权重是后训练难题。依次试了 DPO 和四种 RL 配方，恰好各自踩中一个失败模式：硬门控奖励太稀疏（绝大多数 rollout 得零分、组内优势归零——稀疏性）；分级奖励信号密了但代理指标不对应真实通过率（目标错位）；只给第一轮回复打分逼出敷衍式短答（rollout 形状不匹配）；rollout 形状与评测对齐后训练奖励开始爬升、策略却在几步内塌缩到单一模式、连 4 倍强的 KL 锚都拉不住（训练崩溃）。**没有一种配方越过 SFT 天花板**。换成 On-Policy Distillation（冻结 Qwen3-32B 教师，在学生自己走出的多轮轨迹上逐 token 给目标分布）——训练平滑收敛，四种条件下通过率一律比同源 SFT 基线高出 23 到 47 个百分点。**四种稀疏信号轮番失败、一种稠密信号成功——卡住后训练的往往不是奖励函数设计得不够巧，而是信号本身不够密**。



### 12.2 没有更强的教师怎么办：On-Policy 自蒸馏



- On-Policy Distillation 背上的硬前提：必须有一个明显强于学生的教师模型。训练垂直领域模型时现有模型能力都存在不足，就没有教师可用。

- **On-Policy Self-Distillation（OPSD，在轨自蒸馏）**：让同一个模型分饰教师和学生两角，区别只在上下文。**教师版能看到"特权信息"（privileged information）**——题目的标准答案、已验证的正确解答——它不需要真的"会做"这道题，只需要拿着答案把学生走出的每一步合理化、给出逐 token 目标分布；学生版只看到问题本身，在自己采样的轨迹上向教师版对齐。直觉："对着答案讲题"远比"独立解题"容易——与 RLVR 赖以成立的"验证—生成不对称"同构，只不过这里不对称性被用来产生稠密监督信号而非稀疏成败标量。

- **相比 RLVR 两个核心优势**：①不再依赖可验证奖励——特权信息来源宽得多（标准答案、更丰富系统提示词、人工示范、领域文档，凡是"能让模型事后把正确行为讲清楚"的信息都行）；②监督信号比 RL 密集得多（RL 一条轨迹一个标量奖励，OPSD 轨迹每个位置一个完整概率分布，token 效率明显优于 RL）。

- **边界**：教师能力上限锁在学生自己身上——收益取决于"特权信息能带来多少额外能力"。模型拿着答案也讲不清解题过程时（答案来自穷举搜索而非可用语言解释的推理）自蒸馏没有信号来源。已有研究观察到朴素 OPSD 失败模式（自蒸馏过程中模型逐渐丢失原有思考风格，需额外正则稳定——"Purified OPSD"）。仍在快速演化，但已为"没有更强教师"的普遍困境打开一条路。

## 13. 后训练完整图景与实践要点



- 协同范式："先形后神"（GeneralPoints 实验小结借中国画说明）——结构化输出不稳定的设置中先用 SFT 建立格式和基本能力，再在有可靠奖励与环境时用 RL 探索策略。SFT 稳定协议与结构（JSON 格式、对话模板、工具接口），RL 改善算术规则、空间思考和动作序列的分布外表现。换用其他数据与模型结果可能不同；SFT 训练过度或 RL 优化过度都可能对当前分布过拟合。

- **常见陷阱（识别这些问题往往比掌握技术细节更能避免资源浪费）**：

  1. **过度依赖后训练来记忆事实**——应该用 RAG 管理事实知识（可动态更新、可追溯来源、不因训练而遗忘），后训练聚焦于"如何使用知识"；

  2. **格式未稳定就引入 RL**——模型不能稳定生成奖励计算所需的 JSON 时训练信号稀疏或失真；先用小规模评估设定格式稳定性门槛，必要时通过 SFT 或约束解码稳定输出后再应用 RL；

  3. **奖励函数设计不当导致奖励黑客**——模型学会钻奖励漏洞获得高分而非真正完成任务（只看回复长度就生成冗长无意义文本）；应评估最终目标而非中间指标；

  4. **忽视仿真保真度**——仿真过于简化或环境响应不真实时训练策略在真实场景完全失效；高保真仿真环境构建成本可能高于训练本身；

  5. **过度训练导致泛化下降**——训练损失持续下降但验证集性能恶化时模型正在死记训练细节；SFT 尤其容易出现，早停至关重要；RL 过度优化同样导致策略过拟合当前任务分布；

  6. **价值函数崩溃与探索不足**——PPO 中价值估计不准确导致优势计算偏差、训练曲线剧烈震荡；温度过低或随机性不足使 Agent 陷入局部最优；

  7. **低估 RL 的计算成本**——SFT 上表现良好的任务转 RL 可能需要 10-100 倍训练时间；测试分布与训练高度一致时 SFT 可能已经足够；

  8. **训练数据质量低下**——SFT 直接学习数据噪声与偏差、将错误固化为参数；RL 虽然通过探索可能发现更好策略，但奖励模型有系统性偏差时朝错误方向优化。

  - 核心原则：**在投入大规模资源前，先用小规模实验验证关键假设**——少量数据测试 SFT 能否稳定格式、简化环境验证 RL 能否收敛、小样本检查奖励函数是否反映真实目标。快速失败比大规模失败更可接受。

- **与 RAG/ICL 的协同**：三者不是互斥方案，作用于不同位置。**ICL** 用示例、规则和当前状态实现零参数即时适应（但上下文增长延迟费用上升）；**RAG** 把事实与证据放在可动态更新、可追溯的外部知识中；**后训练**把高维感知、生成风格和隐式决策策略写入参数。选择依据不只是任务是否长期稳定，**更重要的是能力能否被外部符号充分表达**——医疗影像识别、自然语气等能力即使面对持续变化的领域仍往往需要参数更新；长期稳定的转账审批规则应由代码提供确定性保障而不能只靠模型记忆。

- 稳健系统通常组合使用：RAG 管理事实与证据、ICL 快速试验可语言化的策略、程序固化确定性流程与硬约束、难以显式表达且需广泛泛化的能力通过后训练写入参数。后训练还可实现模型蒸馏（高能力大模型能力迁移到成本更低的小模型）。

## 14. 本章小结（书中原文要点）



- 模型后训练的本质是**把交互策略写入参数**。

- SFT 和 RL 与其说是竞争关系，不如说是经常按顺序组合的方法（先 SFT 稳定格式使 RL 奖励可计算，再 RL 探索策略改善分布外表现）。"SFT 记忆、RL 泛化"概括的是本章受控实验中观察到的倾向，**不是不受数据、模型、奖励与环境影响的普遍规律**。

- 两条比任何算法都值得记住的判断：

  - **数据和环境比算法更重要**——现成算法会用就行，真正拉开差距的是仿真环境保真度和训练数据质量；造不出真实环境时用模型模拟环境（合成工具返回值、仿真环境动态）可行但模拟器偏差就是训练天花板；不仅答案可以筛选，训练数据的任务分布本身也可成为优化对象；很多场景只要 SFT 数据质量到位甚至不需要做 RL；

  - **当前 RL 的主要瓶颈是样本效率**——让每一步信号更密集的 On-Policy Distillation、把被浪费环境反馈变成可学习信号的 RLVP（"奖励结果、惩罚路径"、用可达进展的部分奖励救回全败组采样），是目前看起来最有希望的两个方向。共同点仍是那句话——**把环境和数据里本就存在、却被纯结果奖励浪费掉的信息，重新变成模型能学的东西**。没有更强教师时，OPSD 让同一模型以"看答案的教师"和"只见题的学生"两种身份互相监督，把逐 token 稠密信号带到奖励不可验证的任务上。

- 本章回答参数更新"怎样训练"；第八章把模型参数重新放回完整 Agent 系统（参数只是知识、指令、程序与参数四种更新载体之一），讨论如何从部署轨迹获得可信学习信号、选择正确更新位置、治理候选版本验证/发布/回滚。

## 15. 思考题（共 12 道，星级标注）



- ★★ 灾难性遗忘——一次针对特定任务的微调破坏了模型原有的通用能力（如通用工具调用）——在 Agent 场景下尤其棘手。相比全参微调，LoRA 冻结基座权重、遗忘风险更低，但并非免疫。有哪些策略可以进一步缓解微调带来的能力遗忘？

- ★★ 后训练将能力固化为模型权重（"肌肉记忆"），而上下文学习将知识放在推理时的输入中。但有些能力（如领域知识）既可以通过后训练学习，也可以通过 few-shot 示例提供。你会用什么标准来决定某项能力应该走哪条路径？

- ★★ 模型蒸馏让小模型学习大模型的行为。按能力层次，被蒸馏的模型大致可分为三级——Chat 模型（单轮对话、直接作答）、Reasoning 模型（带长链思考再作答）、Agentic 模型（多轮调用工具、与环境交互）。分别蒸馏这三类模型，难点有什么不同？（提示：从"要蒸馏的到底是什么"入手——是输出的风格、完整的思考轨迹，还是与环境交互的决策策略；轨迹里哪些 token 该学、哪些是环境返回的不该学；以及成败信号出现得有多晚、有多稀疏。）

- ★★★ 在多轮 Agent 交互中，奖励的归因（credit assignment）问题比单轮更严重——一个最终的成功或失败很难归因到第 3 轮还是第 7 轮的决策。你会如何设计奖励分配策略？

- ★★★ 如果你有固定预算（比如 $10,000），要提升一个客服 Agent 的性能，你会如何在上下文与知识、Prompt/Skills、程序约束和参数训练之间分配预算？你的决策取决于哪些因素？

- ★★★ 在没有明确奖励函数、样本稀少的情况下，自主实现模型学习，被一些人认为是后训练的终极目标。当前的 RL 训练方法距离这个目标还有多远？你认为下一个突破最可能来自哪个方向？

- ★★ 本章指出 LoRA 微调的成本并不高。那么，是否有可能给每个用户（或每个客户公司）训练一个专属的 LoRA，将用户记忆或企业知识写入参数，而非像第三章那样存储在外部知识库中？在什么场景下，"记忆写入参数" 比 "记忆存入知识库" 更有优势？又在什么场景下会适得其反？

- ★★★ On-Policy Distillation 依赖更强的教师模型来监督学生。但 OpenAI 的 Weak-to-Strong Generalization 研究提出了一个反直觉的发现：弱模型的监督信号有时能激发强模型本身潜在但未被激活的能力。如果将这一思路应用到 Agent 训练，是否可能实现 "小模型教大模型" 的逆向蒸馏？

- ★★ 过程奖励模型（PRM）评估每个思考步骤，而结果奖励模型（ORM）只看最终结果。但"正确的过程导致错误结果"和"错误的过程侥幸得到正确结果"哪个更值得奖励？在 Agent 的多步工具调用场景中，你会如何权衡？

- ★★★ 本章讨论的评估数据集（如 SWE-Bench Verified、τ²-bench、AndroidWorld）既可以用于评估也可以用于后训练。但如果将评估集用于训练，它就不再是独立的评估集——这是否违反了训练集与测试集必须分离的基本原则？τ²-bench 的动态参数生成和 AndroidWorld 的参数化模板在一定程度上缓解了这个问题，但模板结构本身仍然是固定的。如何在充分利用评估数据的训练价值与维护评估独立性之间找到平衡？

- ★★★ 本章提出 "先形后神" 的训练范式：SFT 到 "格式稳定、能力初具" 即止，然后切换到 RL。但实践中，如何判断 SFT 已经 "足够" 而应该切换？

- ★★★ ReTool 的训练动态显示（见实验 7-15），少数超长响应会显著拖长整个训练周期——一批 rollout 里绝大多数已经生成完毕，却要等那几条最长的响应收尾，其间集群的 GPU 利用率很低。如何提升这种长尾响应场景下训练集群的资源利用率？

- ★★★ 用 LLM 模拟环境（如模拟搜索引擎、模拟用户）训练 Agent 时，Agent 钻空子的对象从 "真实环境的规则" 变成了 "模拟器本身的偏见与漏洞"。这类训练中可能出现哪些具体的 reward hacking 行为？又该如何防范？
